# Визуализатор зависимостей Ubuntu APT — вариант №25

CLI-приложение читает индекс репозитория Ubuntu APT, самостоятельно разбирает поля `Package`, `Version`, `Depends` и `Pre-Depends`, строит граф зависимостей алгоритмом BFS без рекурсии и формирует диаграмму PlantUML. Менеджеры пакетов и библиотеки для получения зависимостей не используются.

## Требования

- Python 3.10 или новее.
- PyYAML для чтения конфигурации.
- Для создания PNG: Java и PlantUML, команда `plantuml` должна быть доступна через `PATH`.

## Установка

```bash
python -m venv .venv
# Linux/macOS
. .venv/bin/activate
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
python -m src.main
```

Или с другим конфигурационным файлом:

```bash
python -m src.main --config config.yaml
```

На Linux/macOS можно использовать `./run.sh`, на Windows — `run.bat`.

## Конфигурация

Параметры находятся в `config.yaml`:

- `package` — имя анализируемого пакета.
- `repository_url` — URL индекса `Packages` или `Packages.gz` для нужного выпуска, компонента и архитектуры Ubuntu.
- `test_mode` — `true` включает тестовый источник вместо сетевого индекса.
- `test_repository` — путь к JSON-файлу тестового графа.
- `output_file` — имя PNG-файла.
- `show_ascii` — выводить ли ASCII-дерево.
- `max_depth` — максимальная глубина от корневого пакета; корень имеет глубину 0.

В тестовом режиме имена пакетов должны быть большими латинскими буквами. Формат файла:

```json
{"A": ["B", "C"], "B": ["D"], "C": [], "D": []}
```

## Этапы реализации

1. **Конфигурация:** `src/config.py`, `config.yaml`, `src/main.py`. Проверяются наличие, типы и значения параметров. При запуске настройки выводятся в формате ключ-значение.
2. **Сбор данных:** `src/apt_repository.py`. Индекс загружается стандартным `urllib`, gzip распаковывается стандартным `gzip`, поля Packages разбираются собственным кодом. Для пакета выводятся прямые зависимости.
3. **Основные операции:** `src/graph.py` и `src/main.py`. BFS реализован очередью `deque`, обход ограничен `max_depth`, повторное раскрытие вершин предотвращено, циклы обнаруживаются отдельно. JSON-источник обеспечивает тестовый режим.
4. **Дополнительные операции:** `src/ordering.py`. Итеративный обход формирует порядок, в котором зависимости идут раньше зависимого пакета. При цикле полный порядок не выдаётся.
5. **Визуализация:** `src/visualizer.py`. Создаётся текст PlantUML (`.puml`), затем при установленном PlantUML генерируется PNG. ASCII-дерево включается настройкой `show_ascii`.

## Демонстрация тестового режима

В `config.yaml` установите:

```yaml
package: A
test_mode: true
test_repository: data/test_repository.json
max_depth: 3
```

Затем выполните `python -m src.main`. Для демонстрации цикла используйте `data/test_cycle.json` и `package: A`.

## Ограничения интерпретации APT

- Укажите индекс `Packages`/`Packages.gz` конкретного выпуска, компонента и архитектуры. Индекс может быть большим и загружаться некоторое время.
- В альтернативной зависимости `x | y` выбирается первый вариант `x`; полноценный выбор с учётом установленного состояния, архитектуры и доступности пакетов не выполняется.
- Ограничения версий, профили сборки и квалификаторы архитектуры не разрешаются. Если зависимый пакет отсутствует в загруженном индексе, его вершина остаётся без раскрытых исходящих рёбер.
- Реальный APT может выбирать и устанавливать альтернативы иначе, учитывать уже установленные пакеты, приоритеты, архитектуру и конфликты. Поэтому порядок этого инструмента — учебный топологический порядок графа, а не точная симуляция `apt`.
- Для PNG необходима отдельная установка PlantUML и Java. Если их нет, приложение всё равно сохраняет `.puml` и сообщает, как включить рендеринг.

## Три демонстрационных примера (тестовый граф)

Включите `test_mode: true`, `test_repository: data/test_repository.json` и
последовательно задайте `package: A`, `package: B`, `package: C`.
Каждый запуск создаёт свой `.puml` и PNG (если установлен PlantUML). Ожидаемые
структуры:

- `A`: `A -> B, C`; далее `B -> D`, `C -> D, E`, `D -> F`.
- `B`: `B -> D -> F`.
- `C`: `C -> D, E`; далее `D -> F`.

## Сопоставление с APT

Для реального пакета можно отдельно посмотреть прямые зависимости командой
`apt-cache depends ИМЯ_ПАКЕТА`, а разрешение установки — командой
`apt-get -s install ИМЯ_ПАКЕТА` (режим симуляции). Эти команды используются
только для контрольного сравнения, не внутри программы и не для получения
данных её графа. Возможные различия ожидаемы: APT учитывает альтернативы,
версии, архитектуру, уже установленные пакеты, источники и приоритеты. Наш
учебный анализ выбирает первую альтернативу и строит граф по одному
предоставленному индексу, поэтому его порядок не обязан совпадать с реальным
планом установки APT.
